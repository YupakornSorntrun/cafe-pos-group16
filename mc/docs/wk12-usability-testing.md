เขียนเป็นเป้าหมาย ไม่ระบุขั้นตอนการกดปุ่ม

| Task | มาจาก Use Case/User Story | ประเภท |
|---|---|---|

| O-02 คุณต้องการเปรียบเทียบยอดขายรายเดือนระหว่าง 2 สาขา เพื่อดูว่าสาขาใดมียอดขายมากกว่า คุณจะทำอย่างไร? | ดูรายงานยอดขายแยกตามสาขา | Happy path |
| O-03 ร้านต้องการเพิ่มเมนูใหม่ชื่อ "Iced Mocha" ราคา 65 บาท ในหมวดกาแฟ คุณจะเพิ่มเมนูนี้เข้าสู่ระบบอย่างไร? | จัดการเมนูสินค้า | Happy path |
| O-04 ร้านต้องการปรับราคากาแฟ Latte เป็น 60 บาท คุณจะเปลี่ยนแปลงข้อมูลให้ถูกต้องอย่างไร? | แก้ไขข้อมูลเมนูสินค้า | Happy path |
| O-05 คุณได้รับข้อมูลราคาสินค้าใหม่เป็น -10 บาท ซึ่งเป็นข้อมูลผิดพลาด หากลองใช้ราคานี้ในการแก้ไขเมนู ระบบจะตอบสนองอย่างไร? | ตรวจสอบความถูกต้องของข้อมูลเมนู | Error path |

### 1.2 Task สำหรับพนักงานแคชเชียร์

| Task | มาจาก Use Case/User Story | ประเภท |
|---|---|---|
| C-01 ลูกค้าสั่งอเมริกาโน่เย็น 1 แก้ว และลาเต้ร้อน 1 แก้ว ชำระเงินด้วยเงินสด คุณจะทำการบันทึกออเดอร์นี้และกดยืนยันการชำระเงินอย่างไร? | การรับออเดอร์และการชำระเงิน | Happy path |
| C-02 คุณเผลอกดเพิ่มเอสเพรสโซ่ลงไปในตะกร้า 2 แก้ว แต่ลูกค้าสั่งแค่ 1 แก้ว คุณจะลดจำนวนสินค้าหรือลบรายการนี้ออกจากตะกร้าก่อนกดชำระเงินอย่างไร? | แก้ไข/ลบรายการสินค้าในตะกร้า | Happy path |

| C-04 ลูกค้าต้องการสั่งครัวซองต์ แต่สินค้านั้นถูกตั้งค่าในระบบว่าหมด หากคุณพยายามกดเลือกสินค้านั้นลงตะกร้า ระบบจะแสดงผลอย่างไร? | สินค้าคงเหลือไม่เพียงพอ | Error path |
| C-05 เมื่อกดชำระเงินออเดอร์เรียบร้อยแล้ว แต่ลูกค้าขอเปลี่ยนใจยกเลิกออเดอร์กะทันหัน คุณจะทำการยกเลิกบิลที่ชำระเงินไปแล้วอย่างไร? | ยกเลิกคำสั่งซื้อ | Error path |
| C-06 ลูกค้าชำระเงินเสร็จไปแล้วเมื่อ 10 นาทีที่แล้ว แต่เดินกลับมาขอใบเสร็จรับเงินย้อนหลัง คุณจะเข้าไปค้นหาประวัติบิลที่เพิ่งขายไปและกดพิมพ์ใบเสร็จซ้ำออกมาใหม่อีกครั้งอย่างไร? | ดูประวัติการขายและพิมพ์ใบเสร็จย้อนหลัง | Happy path |
| C-07 ลูกค้าต้องการใช้สิทธิ์ส่วนลด 10% หรือใช้คูปองส่วนลดสำหรับออเดอร์นี้ คุณจะกรอกรหัสส่วนลดหรือหักลบราคาในระบบก่อนคิดเงินรวมอย่างไร? | การจัดการส่วนลด | Happy path |

> task ที่ผู้ทดสอบให้ feedback ในรอบนี้คือ C-03, C-04 และ C-06

## 2. บันทึก Think-Aloud

คำพูดของผู้ทดสอบจริงที่ให้เป็น feedback หลังทำ task

### Task C-03: ยอดเงินชำระไม่ครบ

> "ช่องกรอกเงินสดรับมาสีดูอ่อนมากจนกลืนไปกับหน้าจอ ตาเผลอมองข้ามไปมองจุดอื่นก่อน กว่าจะหาเจอว่าต้องกรอกจำนวนเงินตรงไหน"

### Task C-04: สินค้าคงเหลือไม่เพียงพอ

> "ตอนกดเลือกของลงตะกร้ากดเพิ่มได้เรื่อย ๆ เลยไม่รู้ว่าสต็อกเหลือเท่าไร ระบบเพิ่งมาเตือนว่า 'วัตถุดิบไม่พอ' ตอนกดชำระเงินแล้ว ทำให้เสียเวลา ควรเตือนตั้งแต่ตอนกดเลือกสินค้า และควรแสดงจำนวนคงเหลือในสต็อกให้เห็นด้วย"

### Task C-06: ดูประวัติการขายและพิมพ์ใบเสร็จย้อนหลัง

> "เมนูประวัติ/รวมออเดอร์หายาก น่าจะแยกออกมาเป็นอีกแท็บให้เห็นชัด ๆ ส่วนฟังก์ชันการยกเลิก แสดงคิว แสดงยอด และการพิมพ์ใบเสร็จทำได้ดีแล้ว"

## 3. รายการ Usability Issue

### Issue #1

- คำอธิบายปัญหา: ช่องกรอกเงินสดที่รับจากลูกค้ามีสีอ่อนมากจนกลืนไปกับหน้าจอ ผู้ทดสอบมองข้ามไปที่จุดอื่นก่อน กว่าจะพบว่าต้องกรอกจำนวนเงินตรงไหน
- Task ที่เกี่ยวข้อง: C-03
- ความถี่: 1 ครั้ง จากผู้ทดสอบ 1 คน
- หลักการที่เกี่ยวข้อง: Visibility
- Severity: **Minor**

### Issue #2

- คำอธิบายปัญหา: ตอนเลือกสินค้าลงตะกร้ากดเพิ่มได้เรื่อย ๆ และไม่แสดงจำนวนคงเหลือในสต็อก ระบบเพิ่งเตือน "วัตถุดิบไม่พอ" ตอนกดชำระเงิน ทำให้เสียเวลา
- Task ที่เกี่ยวข้อง: C-04
- ความถี่: 1 ครั้ง จากผู้ทดสอบ 1 คน
- หลักการที่เกี่ยวข้อง: Error Prevention, Feedback, Visibility
- Severity: **Major**

### Issue #3

- คำอธิบายปัญหา: เมนูประวัติ/รวมออเดอร์หาได้ยาก ผู้ทดสอบเสนอให้แยกเป็นแท็บที่เห็นชัด (ส่วนฟังก์ชันยกเลิก แสดงคิว แสดงยอด และพิมพ์ใบเสร็จ ผู้ทดสอบเห็นว่าทำได้ดีแล้ว)
- Task ที่เกี่ยวข้อง: C-06
- ความถี่: 1 ครั้ง จากผู้ทดสอบ 1 คน
- หลักการที่เกี่ยวข้อง: Visibility
- Severity: **Major**

> Severity เป็นการประเมินของกลุ่มเจ้าของ UI ตามเกณฑ์หัวข้อ 3.2 ของ wk12.md

## 4. การแก้ไข / แผนการแก้ไข

| Issue # | Severity | สถานะ | รายละเอียด |
|---|---|---|---|
| #2 | Major | แก้ไขแล้ว | เพิ่มการตรวจสอบสต็อกทันทีเมื่อกดเลือกสินค้า พร้อมแสดงข้อความ "วัตถุดิบไม่พอ" และไม่ให้กดเพิ่มลงตะกร้าตั้งแต่ขั้นตอนแรก (หน้า POS แสดง "เหลือ N" บนการ์ดเมนู เตือนทันทีและหยุดเพิ่มเมื่อถึงจำนวนที่ขายได้ โดย `GET /api/menu` ส่ง `available_qty` เพิ่ม ส่วน server ยังตรวจสต็อกซ้ำตอนชำระเงิน) |

| #1 | Minor | แก้ไขแล้ว | ปรับสีพื้นหลังและเส้นขอบของช่องกรอกเงิน เพิ่มความต่างของปุ่มเพื่อสร้าง Visual Hierarchy ให้ชัดเจน (ช่อง "รับเงินมา" ขอบหนาสีเข้ม พื้นขาว ตัวหนา ป้ายกำกับตัวหนา และปุ่มลัดเงินมีขอบเข้มขึ้น) |

## AI Disclosure (Week 12)

1. ใช้ AI หรือไม่: **ใช้ AI**
2. เครื่องมือ: ChatGPT (OpenAI), Google Gemini
3. งานส่วนที่ใช้ AI: ช่วยร่าง Task สำหรับ Usability Testing แยกบทบาท Owner/Cashier, จัดประเภท Happy/Error path, จัดรูปแบบตารางและปรับถ้อยคำให้ไม่ชี้นำผู้ทดสอบ
4. Prompt ตัวอย่าง: "ช่วยคิดคำถามสำหรับนำไปทดสอบกับผู้ใช้อื่นที่ใช้งานหน้าเว็บเป็นครั้งแรก โดยแบ่งประเภทออกเป็น เจ้าของร้าน กับ พนักงานแคชเชียร์ ทำออกมาเป็นตาราง Task ที่ใช้ทดสอบ" (ให้บริบทระบบ POS, wk12.md และเทมเพลต)
5. ผลลัพธ์จาก AI: ร่างตาราง Task เจ้าของร้าน 5 ข้อ และแคชเชียร์ 7 ข้อ พร้อมประเภท Happy/Error path และรูปแบบตารางบันทึกผล
6. การปรับแต่งของนิสิต: กำหนดขอบเขตการแบ่งบทบาทตามสิทธิ์ที่ออกแบบใน wk10, คัดเลือก Task ที่ตรงกับฟังก์ชันจริง; การทดสอบ การสังเกต การบันทึก think-aloud และการประเมิน issue/severity ทำโดยนิสิตที่เป็นผู้ทดสอบจริง ไม่ได้ให้ AI ทำแทน
7. เหตุผล: ระบบมีฟังก์ชันต่างกันตามบทบาท ใช้ AI เสนอสถานการณ์ที่หลากหลายและลดเวลาจัดทำตาราง นิสิตเป็นผู้ตัดสินใจเลือกและปรับให้ตรงระบบจริง
8. เอกสารต้นทาง: wk03-requirements.md, wk04-user-stories.md, wk10-input-output-design.docx, wk10-wireframe.docx, wk12.md, wk12-usability-testing-template.md
9. ส่วนที่ AI ช่วยเขียน: ร่างตาราง Task, จัดประเภท Happy/Error path, เสนอรูปแบบตารางบันทึกผล (ไม่มีการเขียนหรือแก้ไข Source Code)
10. สมาชิกที่อธิบายงานได้: ผู้รับผิดชอบจัดทำ Usability Testing อธิบายวัตถุประสงค์ของ Task การแบ่งบทบาท และความต่าง Happy/Error path; ผู้ดำเนินการทดสอบอธิบายวิธีเก็บข้อมูลและผลที่สังเกตได้
11. โค้ด/schema/สถาปัตยกรรมต่างจาก diagram เดิมหรือไม่: ไม่ต่าง
12. ข้อจำกัดที่ทราบ: ต้องเตรียมข้อมูลทดสอบ (สินค้า ยอดขาย สต็อก สาขา) ก่อนเริ่ม; ผลทดสอบมาจากผู้ทดสอบ 1 คน และมีเฉพาะฝั่งแคชเชียร์
