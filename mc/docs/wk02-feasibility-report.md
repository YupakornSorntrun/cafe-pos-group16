# Workshop (ในห้องเรียน)

## คำถาม 1

    แต่ละกลุ่มร่างรายงานความเป็นไปได้อย่างย่อ ตามโครงสร้างในหัวข้อ 1.3 โดยอ้างอิงบริบทร้านกาแฟ 3-5 สาขาตามโจทย์ในสัปดาห์ที่ 1

## ตอบ

| หัวข้อ | เนื้อหา |
|:-----|:-----|
| **ภาพรวมโครงการ** | ระบบ POS จัดการร้านกาแฟ 3-5 สาขา เพื่อลดเวลาคิดเงิน, ตัดสต็อกวัตถุดิบอัตโนมัติ และรายงานยอดขายรายวัน ผู้ใช้หลักคือ พนักงานหน้าร้าน, บาริสต้า, เจ้าของร้าน/ผู้จัดการร้าน, พนักงานบัญชี, ฝ่ายจัดซื้อ |
| **Technical Feasibility** (ความเป็นไปได้ด้านเทคนิค) |  ทีมพัฒนามีทักษะ Node.js/Express และ MySQL ในระดับปานกลาง โดยระบบจะรองรับ Hardware หน้าร้าน เช่น เครื่อง POS, แท็บเล็ตรับออเดอร์, เครื่องพิมพ์ใบเสร็จ, จอแสดงผลฝั่งลูกค้า และเครื่องสแกนบาร์โค้ด/QR Code แต่มีความเสี่ยงที่ต้องระวัง ในส่วนการเขียนโปรแกรมเชื่อมต่ออุปกรณ์จริง |
| **Economic Feasibility** (ความเป็นไปได้ด้านเศรษฐศาสตร์) | ต้นทุนค่าพัฒนาระบบ และค่าอุปกรณ์ รวมประมาณ 60,000 - 80,000 บาท ผลที่คาดว่าได้รับ คือ ช่วยลดขั้นตอนรับออเดอร์และคิดเงินด้วยมือ, ช่วยลดข้อผิดพลาดในการตัดสต๊อก และช่วยประหยัดเวลาปิดยอดขายประจำวันได้มากกว่า 30 นาทีต่อวัน คาดว่าจะสามารถคืนทุนได้ภายในระยะเวลา 6 เดือน |
| **Operational Feasibility** (ความเป็นไปได้ด้านการปฏิบัติงาน) | พนักงานหน้าร้านที่คุ้นเคยกับการใช้กระดาษอาจต้องปรับตัวในช่วงแรก ทีมพัฒนาจึงจะเน้นด้านการออกแบบ UI ให้ใช้งานง่ายที่สุด พร้อมเตรียมแผนจัดอบรมพนักงาน ให้สามารถเรียนรู้การใช้งานพื้นฐานของระบบได้ภายใน 30 - 60 นาทีต่อคน โดยมีเจ้าของร้านสนับสนุนอย่างเต็มที่| 
| **Schedule Feasibility** (ความเป็นไปได้ด้านระยะเวลา) | มีเวลา 16 สัปดาห์ โดย สัปดาห์ 1-4 สำหรับวิเคราะห์และออกแบบ, สัปดาห์ 5-12 สำหรับพัฒนา และสัปดาห์ 13-16 สำหรับทดสอบและนำเสนอ |
| **ข้อสรุป** | ควรดำเนินโครงการต่อ เนื่องจากผลประโยชน์คุ้มค่าต้นทุน และทีมมีความพร้อมด้านเทคนิคและเวลาเพียงพอ |

## คำถาม 4

    อภิปรายในกลุ่มว่า BPMN แบบ To-Be ช่วยแก้ปัญหาที่ระบุใน Operational และ Economic Feasibility อย่างไร

## คำตอบ


- **Operational Feasibility** - เมื่อก่อนในการรับออเดอร์ลูกค้าจะเป็นการจดออเดอร์ด้วยมือ ซึ่งอาจจะทำให้รับออเดอร์ช้าหรือมีตกหล่นไปได้บ้าง ดังนั้นถ้านำระบบ POS มาใช้จะช่วยลดความสับสนในการทำงานของพนักงาน และลดการจดบันทึกด้วยมือ หากออกแบบหน้าจอระบบให้ใช้งานง่าย และมีการอบรมการใช้งานก่อนเริ่มใช้จริง จะช่วยให้พนักงานสามารถปรับตัวได้ง่าย 

- **Economic Feasibility** - การเพิ่มต้นทุนในการพัฒนาระบบ POS ในด้าน Hardware และ Software แม้ว่าจะต้องเพิ่มต้นทุนมากขึ้นแต่เมื่อเทียบกับความคุ้มค่าด้านเวลาและลดข้อผิดพลาดต่าง ๆ การลงทุนกับระบบจะทำให้ลดขั้นตอนที่ซ้ำซ้อน ลดความผิดพลาดในการรับออเดอร์ การคิดเงิน และการตัดสต็อก ส่งผลให้พนักงานใช้เวลาทำงานน้อยลง และลดต้นทุนแรงงานในระยะยาว แม้ว่าจะมีต้นทุนเริ่มต้น เช่น ค่าเครื่อง POS, แท็บเล็ตรับออเดอร์, เครื่องพิมพ์ใบเสร็จ, จอแสดงผลฝั่งลูกค้า และเครื่องสแกนบาร์โค้ด-คิวอาร์โค้ด และค่าพัฒนาระบบ แต่ผลประโยชน์ที่ได้รับ จะประหยัดเวลาสรุปยอดขายไปได้มากกว่า 30 นาทีต่อวัน
