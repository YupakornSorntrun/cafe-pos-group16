# User Story
แปลง Functional Requirement `(wk03-requirements.md)` แต่ละข้อเป็น User Story

| Functional Requirement | User Story | Acceptance Criteria |
| :--- | :--- | :--- |
| **FR-01:** ระบบต้องสามารถบันทึกรายการออเดอร์ของลูกค้า พร้อมระบุเลขโต๊ะ หรือประเภทการทาน | **As a** พนักงานแคชเชียร์  <br>**I want** เลือกประเภทการทาน เช่น ทานที่ร้าน สั่งกลับบ้าน หรือเดลิเวอรี และระบุเลขโต๊ะได้เมื่อสร้างออเดอร์ใหม่  <br>**So that** ข้อมูลออเดอร์ถูกต้องและตรงกับความต้องการของลูกค้า | **Scenario 1: บันทึกออเดอร์แบบทานที่ร้าน**  <br>• **Given** พนักงานอยู่ในหน้าจอสร้างออเดอร์ใหม่  <br>• **When** พนักงานเลือกประเภทการทานเป็น "ทานที่ร้าน" และกรอกระบุเลขโต๊ะ พร้อมเลือกรายการอาหาร  <br>• **Then** ระบบต้องบันทึกข้อมูลออเดอร์พร้อมแสดงเลขโต๊ะ บนบิลและหน้าจอสรุปออเดอร์อย่างชัดเจน  <br><br>**Scenario 2: บันทึกออเดอร์แบบกลับบ้าน**  <br>• **Given** พนักงานอยู่ในหน้าจอสร้างออเดอร์ใหม่  <br>• **When** พนักงานเลือกประเภทการทานเป็นกลับบ้าน  <br>• **Then** ระบบต้องข้ามช่องระบุเลขโต๊ะและบันทึกสถานะออเดอร์เป็นประเภทกลับบ้านทันที |
| **FR-02:** ระบบต้องสามารถคำนวณยอดเงินรวม ค่าทอนเงิน และแสดงยอดชำระเงินได้อย่างถูกต้องแม่นยำ | **As a** พนักงานแคชเชียร์  <br>**I want** ให้ระบบคำนวณยอดเงินรวมทั้งหมดของรายการอาหารและคำนวณเงินทอนอัตโนมัติเมื่อป้อนจำนวนเงินที่รับมา  <br>**So that** ป้องกันความผิดพลาดในการทอนเงินและรวดเร็วในการชำระเงิน | **Scenario 1: คำนวณยอดรวมและเงินทอนถูกต้อง**  <br>• **Given** ออเดอร์มียอดชำระรวมทั้งสิ้น 350 บาท  <br>• **When** แคชเชียร์กรอกจำนวนเงินที่รับจากลูกค้ามา 500 บาท  <br>• **Then** ระบบต้องคำนวณและแสดงผลเงินทอนที่ต้องคืนลูกค้าเท่ากับ 150 บาทอย่างถูกต้อง  <br><br>**Scenario 2: แจ้งเตือนเมื่อเงินสดไม่พอชำระ**  <br>• **Given** ออเดอร์มียอดชำระรวม 350 บาท  <br>• **When** แคชเชียร์กรอกจำนวนเงินที่รับมา 300 บาท  <br>• **Then** ระบบต้องแสดงข้อความแจ้งเตือนว่า "จำนวนเงินไม่เพียงพอ" และไม่อนุญาตให้กดบันทึกการชำระเงิน |
| **FR-03:** ระบบต้องสามารถส่งข้อมูลออเดอร์และแสดงผลลำดับคิวบนหน้าจอฝั่งบาริสต้าได้ | **As a** บาริสต้าหรือพนักงานในครัว  <br>**I want** เห็นรายการออเดอร์ใหม่และลำดับคิวแสดงขึ้นบนหน้าจอฝั่งครัวแบบเรียลไทม์ทันทีเมื่อมีการยืนยันออเดอร์  <br>**So that** สามารถเริ่มเตรียมเครื่องดื่มหรืออาหารตามลำดับก่อน-หลังได้อย่างถูกต้อง | **Scenario 1: ออเดอร์ใหม่ปรากฏบนหน้าจอฝั่งครัวทันที**  <br>• **Given** พนักงานแคชเชียร์กดยืนยันการชำระเงินและส่งออเดอร์เรียบร้อยแล้ว  <br>• **When** ระบบประมวลผลออเดอร์สำเร็จ  <br>• **Then** รายการออเดอร์และหมายเลขคิวจะต้องปรากฏขึ้นบนหน้าจอแสดงผลฝั่งบาริสต้าทันทีโดยไม่ต้องรีเฟรชหน้าจอ  <br><br>**Scenario 2: อัปเดตสถานะออเดอร์เป็นกำลังเตรียม**  <br>• **Given** บาริสต้าเห็นคิวออเดอร์บนหน้าจอ  <br>• **When** บาริสต้ากดปุ่ม "กำลังทำ" ที่รายการออเดอร์นั้น  <br>• **Then** สถานะบนหน้าจอต้องเปลี่ยนเป็นสีหรือข้อความที่แสดงว่ากำลังดำเนินการ เพื่อให้ทีมงานคนอื่นรับทราบ |
| **FR-04:** ระบบต้องสามารถจัดการข้อมูลวัตถุดิบและตัดจำนวนสต็อกอัตโนมัติหลังการชำระเงินเสร็จสมบูรณ์ | **As a** ผู้จัดการร้าน  <br>**I want** ให้ระบบตัดจำนวนวัตถุดิบในคลังสินค้าโดยอัตโนมัติทันทีที่มีการชำระเงินออเดอร์เสร็จสมบูรณ์  <br>**So that** ข้อมูลสต็อกสินค้าคงเหลือมีความเป็นปัจจุบันเสมอโดยไม่ต้องมาหักลบด้วยมือ | **Scenario 1: ตัดสต็อกวัตถุดิบอัตโนมัติหลังจ่ายเงิน**  <br>• **Given** สต็อกเมล็ดกาแฟ มีจำนวนคงเหลือ 1,000 กรัม และเมนู Latte ใช้เมล็ดกาแฟ 20 กรัม  <br>• **When** ลูกค้าสั่งและชำระเงินค่าเมนู Latte จำนวน 1 แก้วสำเร็จ  <br>• **Then** ระบบต้องทำการหักลบสต็อกเมล็ดกาแฟอัตโนมัติ เหลือจำนวนคงเหลือ 980 กรัมในระบบหลังบ้าน  <br><br>**Scenario 2: แจ้งเตือนเมื่อวัตถุดิบไม่เพียงพอ**  <br>• **Given** สต็อกนมสด เหลืออยู่ 50 มิลลิลิตร และเมนูที่สั่งต้องใช้นมสด 150 มิลลิลิตร  <br>• **When** พนักงานพยายามบันทึกขายเมนูนั้น  <br>• **Then** ระบบต้องแจ้งเตือนว่า "วัตถุดิบในสต็อกไม่เพียงพอ" เพื่อให้ตรวจสอบก่อนทำรายการ |
| **FR-05:** ระบบต้องสามารถแสดงผลจำนวนคงเหลือของวัตถุดิบในคลังสินค้า โดยจำแนกตามหมวดหมู่ได้อย่างชัดเจน | **As a** พนักงานสต็อกสินค้าหรือผู้จัดการร้าน  <br>**I want** ดูรายการวัตถุดิบคงเหลือในคลังที่ถูกจัดแยกเป็นหมวดหมู่  <br>**So that** สามารถตรวจสอบปริมาณสินค้าแต่ละหมวดหมู่ได้อย่างรวดเร็วและวางแผนสั่งซื้อได้ง่ายขึ้น | **Scenario 1: แสดงหมวดหมู่วัตถุดิบชัดเจน** <br>• **Given** ผู้ใช้งานเข้าสู่หน้าจอจัดการคลังสินค้า <br>• **When** ระบบแสดงรายการวัตถุดิบทั้งหมด  <br>• **Then** วัตถุดิบจะต้องถูกจัดกลุ่มแสดงผลแยกตามหมวดหมู่อย่างเป็นระเบียบ  <br><br>**Scenario 2: ค้นหาและกรองวัตถุดิบตามหมวดหมู่**  <br>• **Given** ผู้ใช้อยู่ในหน้าจอคลังสินค้า  <br>• **When** ผู้ใช้คลิกเลือกตัวกรองเฉพาะหมวดหมู่ผลิตภัณฑ์นม  <br>• **Then** ระบบต้องแสดงเฉพาะรายการวัตถุดิบที่อยู่ในหมวดนมพร้อมจำนวนคงเหลือปัจจุบันทันที |
| **FR-06:** ระบบต้องสามารถออกใบเสร็จรับเงินให้แก่ลูกค้าได้ | **As a** ลูกค้าหรือพนักงานแคชเชียร์  <br>**I want** ให้ระบบสามารถพิมพ์หรือออกใบเสร็จรับเงินที่มีรายละเอียดรายการสินค้า, ราคา และยอดรวมได้อย่างครบถ้วน  <br>**So that** ลูกค้ามีหลักฐานการชำระเงินและร้านค้ามีหลักฐานอ้างอิงในการตรวจสอบยอด | **Scenario 1: พิมพ์ใบเสร็จอัตโนมัติหลังชำระเงินสำเร็จ**  <br>• **Given** พนักงานทำการบันทึกรับเงินและปิดการขายออเดอร์เรียบร้อยแล้ว  <br>• **When** การทำรายการเสร็จสิ้นสมบูรณ์  <br>• **Then** ระบบต้องสั่งพิมพ์ใบเสร็จผ่านเครื่องพิมพ์โดยอัตโนมัติ หรือแสดงตัวเลือกดาวน์โหลดใบเสร็จดิจิทัล  <br><br>**Scenario 2: ข้อมูลในใบเสร็จครบถ้วนถูกต้อง**  <br>• **Given** ใบเสร็จถูกพิมพ์ออกมาจากระบบ  <br>• **When** ตรวจสอบเนื้อหาภายในใบเสร็จ  <br>• **Then** ต้องปรากฏชื่อร้าน, วันที่-เวลา, รายการสินค้าที่สั่ง, จำนวนเงินรวม, และจำนวนเงินทอนอย่างถูกต้องครบถ้วน |
| **FR-07:** ระบบต้องสามารถสรุปและแสดงรายงานยอดขายรายวัน รายเดือน และแยกตามสาขาได้ | **As a** เจ้าของร้านหรือผู้บริหาร  <br>**I want** เรียกดูรายงานสรุปยอดขายทั้งแบบรายวัน รายเดือน และสามารถแยกดูตามรายสาขาได้  <br>**So that** นำข้อมูลมาวิเคราะห์ผลประกอบการและวางแผนธุรกิจได้อย่างแม่นยำ | **Scenario 1: เรียกดูรายงานยอดขายรายวันและรายเดือน**  <br>• **Given** ผู้บริหารเข้าสู่หน้าจอรายงานยอดขาย <br>• **When** ผู้บริหารเลือกช่วงเวลาดูรายงานเป็นรายวันหรือรายเดือน  <br>• **Then** ระบบต้องแสดงกราฟหรือตารางสรุปยอดขายรวมของช่วงเวลานั้น ๆ ได้อย่างถูกต้อง  <br><br>**Scenario 2: กรองรายงานแยกตามสาขา**  <br>• **Given** ร้านค้ามีระบบรองรับหลายสาขา และผู้บริหารต้องการตรวจสอบยอดเฉพาะสาขา  <br>• **When** ผู้บริหารเลือกฟิลเตอร์ระบุสาขา A  <br>• **Then** ระบบต้องแสดงผลสรุปยอดขายเฉพาะของสาขา A โดยไม่นำยอดของสาขาอื่นมารวม |
| **FR-08:** ระบบต้องสามารถวิเคราะห์ข้อมูลยอดขายเพื่อแสดงอันดับเมนูยอดนิยมได้ | **As a** เจ้าของร้านหรือฝ่ายการตลาด  <br>**I want** ระบบจัดอันดับและแสดงรายชื่อเมนูขายดี จากข้อมูลประวัติการขาย  <br>**So that** ทราบว่าเมนูใดได้รับความนิยมสูงสุด เพื่อนำไปใช้จัดโปรโมชันหรือวางแผนวัตถุดิบได้เหมาะสม | **Scenario 1: แสดงรายการเมนูยอดนิยม**  <br>• **Given** มีประวัติการขายสินค้าสะสมภายในระบบ  <br>• **When** ผู้ใช้งานเปิดหน้าจอวิเคราะห์เมนูยอดนิยม <br>• **Then** ระบบต้องแสดงรายการเมนูอาหารหรือเครื่องดื่มเรียงลำดับจากยอดขายสูงสุดไปต่ำสุดพร้อมจำนวนแก้วหรือจานที่ขายได้  <br><br>**Scenario 2: กรองอันดับเมนูตามช่วงเวลาที่กำหนด**  <br>• **Given** ผู้ใช้อยู่ในหน้าจอวิเคราะห์เมนูยอดนิยม  <br>• **When** ผู้ใช้กำหนดช่วงเวลาค้นหาเป็นสัปดาห์นี้หรือเดือนนี้  <br>• **Then** ระบบต้องทำการคำนวณและแสดงผลอันดับเมนูยอดนิยมเฉพาะในช่วงเวลาที่ถูกเลือกนั้นทันที |

## Use Case Description

**Use Case:** รับออเดอร์และคำนวณราคา

**Actor:** พนักงาน

**Precondition:**
พนักงานเข้าสู่ระบบเรียบร้อยแล้ว และระบบพร้อมรับออเดอร์

**Main Flow:**
1. พนักงานเลือกเมนูอาหารหรือเครื่องดื่มที่ลูกค้าต้องการ
2. ระบบแสดงรายการและราคาของสินค้าที่เลือก
3. พนักงานเลือกประเภทการทาน เช่น ทานที่ร้านหรือกลับบ้าน
4. หากทานที่ร้าน พนักงานระบุเลขโต๊ะ
5. ระบบคำนวณยอดรวมของออเดอร์
6. พนักงานเลือกวิธีชำระเงิน
7. พนักงานรับเงินจากลูกค้า
8. ระบบตรวจสอบจำนวนเงินที่รับ
9. ระบบคำนวณเงินทอน
10. ระบบบันทึกออเดอร์และสถานะการชำระเงิน
11. ระบบส่งข้อมูลออเดอร์ไปยังบาริสต้า
12. ระบบออกใบเสร็จให้ลูกค้า

**Alternative Flow:**

3a. ลูกค้าเลือกทานแบบกลับบ้าน
- ระบบไม่ต้องให้ระบุเลขโต๊ะ
- ดำเนินการต่อไปยังขั้นตอนเลือกวิธีชำระเงิน

5a. ลูกค้าใช้ส่วนลด
- พนักงานเลือกส่วนลดที่สามารถใช้ได้
- ระบบคำนวณยอดเงินหลังหักส่วนลด
- ดำเนินการต่อไปยังขั้นตอนเลือกวิธีชำระเงิน

**Exception Flow:**

8a. จำนวนเงินไม่เพียงพอ
- ระบบแจ้งเตือนว่า "จำนวนเงินไม่เพียงพอ"
- ระบบไม่บันทึกการชำระเงิน
- พนักงานรับเงินเพิ่มหรือแก้ไขจำนวนเงิน

8b. วัตถุดิบไม่เพียงพอ
- ระบบแจ้งเตือนว่าวัตถุดิบไม่เพียงพอ
- ระบบไม่อนุญาตให้ยืนยันออเดอร์ที่ไม่สามารถจัดเตรียมได้

**Postcondition:**

- **สำเร็จ:** ระบบบันทึกออเดอร์และการชำระเงิน ส่งออเดอร์ไปยังบาริสต้า และออกใบเสร็จ
- **ไม่สำเร็จ:** ระบบไม่บันทึกการชำระเงินหรือออเดอร์ที่มีปัญหา และแสดงข้อความแจ้งข้อผิดพลาด

| **US-01: รับออเดอร์และคำนวณราคา** | **As a:** พนักงาน<br> **I want:** เลือกรายการสินค้าและให้ระบบคำนวณยอดรวมอัตโนมัติ<br>**So that:** สามารถรับออเดอร์และทราบยอดที่ลูกค้าต้องชำระได้อย่างถูกต้อง | **AC-01: ต้องมีรายการสินค้า**<br> • **Given** พนักงานกำลังสร้างออเดอร์<br>• **When** พนักงานยืนยันออเดอร์โดยไม่มีรายการสินค้า<br>• **Then** ระบบต้องแสดงข้อความว่า "ต้องมีรายการสินค้าอย่างน้อย 1 รายการ" และไม่บันทึกออเดอร์<br><br>**AC-02:** ข้อมูลสินค้าต้องครบถ้วน <br>•  **Given** พนักงานกำลังสร้างออเดอร์<br>• **When** รายการสินค้าใดไม่มีชื่อสินค้า หรือข้อมูลที่จำเป็นไม่ครบ<br>• **Then** ระบบต้องแสดงข้อความแจ้งข้อมูลที่ไม่ครบ และไม่บันทึกออเดอร์<br><br>**AC-03:** ราคาสินค้าต้องมากกว่า 0 <br>• **Given** พนักงานกำลังสร้างออเดอร์<br>• **When** รายการสินค้าใดมีราคาน้อยกว่าหรือเท่ากับ 0<br>• **Then** ระบบต้องแสดงข้อความว่า "ราคาสินค้าต้องมากกว่า 0" และไม่บันทึกออเดอร์<br><br>**AC-04:** จำนวนสินค้าต้องมากกว่า 0 <br>• **Given** พนักงานกำลังสร้างออเดอร์<br>• **When** รายการสินค้าใดมีจำนวนน้อยกว่าหรือเท่ากับ 0<br>• **Then** ระบบต้องแสดงข้อความว่า "จำนวนสินค้าต้องมากกว่า 0" และไม่บันทึกออเดอร์<br><br>**AC-05:** คำนวณยอดรวมถูกต้อง <br> • **Given** พนักงานเลือกสินค้าและระบุราคาและจำนวนถูกต้อง<br>• **When** พนักงานยืนยันออเดอร์<br>• **Then** ระบบต้องคำนวณยอดรวมจากราคาสินค้า × จำนวน และแสดงยอดรวมที่ถูกต้อง |
| **US-02: ระบุประเภทการทาน** | **As a:** พนักงาน<br>**I want:** ระบุประเภทการทานของลูกค้าว่าทานที่ร้านหรือกลับบ้าน<br>**So that:** ระบบสามารถจัดการข้อมูลออเดอร์ได้ถูกต้อง | **AC-01:** ทานที่ร้านต้องระบุเลขโต๊ะ <br>• **Given** พนักงานเลือกประเภทการทานเป็น "ทานที่ร้าน"<br>• **When** พนักงานยืนยันออเดอร์โดยไม่ได้ระบุเลขโต๊ะ<br>• **Then** ระบบต้องแสดงข้อความว่า "กรุณาระบุเลขโต๊ะ" และไม่ยืนยันออเดอร์<br><br>**AC-02:** กลับบ้านไม่ต้องระบุเลขโต๊ะ <br>• **Given** พนักงานเลือกประเภทการทานเป็น "กลับบ้าน"<br>• **When** พนักงานยืนยันออเดอร์โดยไม่ได้ระบุเลขโต๊ะ<br>• **Then** ระบบต้องยอมรับออเดอร์และดำเนินการต่อโดยไม่ต้องระบุเลขโต๊ะ |
| **US-03: ใช้ส่วนลด** | **As a:** พนักงาน<br>**I want:** เลือกส่วนลดที่สามารถใช้กับออเดอร์ได้<br>**So that:** ระบบสามารถคำนวณยอดชำระหลังหักส่วนลดได้อย่างถูกต้อง | **AC-01:** คำนวณยอดหลังหักส่วนลด <br>• **Given** พนักงานมีออเดอร์ที่สามารถใช้ส่วนลดได้<br>• **When** พนักงานเลือกส่วนลดและยืนยันการใช้ส่วนลด<br>• **Then** ระบบต้องคำนวณยอดชำระใหม่โดยหักส่วนลดออกจากยอดรวม |
| **US-04: ชำระเงินและคำนวณเงินทอน** | **As a:** พนักงาน<br>**I want:** รับเงินจากลูกค้าและให้ระบบตรวจสอบจำนวนเงินพร้อมคำนวณเงินทอน<br>**So that:** สามารถรับชำระเงินได้อย่างถูกต้อง | **AC-01:** ตรวจสอบจำนวนเงิน <br>• **Given** ระบบแสดงยอดเงินที่ลูกค้าต้องชำระ<br>• **When** พนักงานกรอกจำนวนเงินที่ลูกค้าชำระ<br>• **Then** ระบบต้องตรวจสอบว่าจำนวนเงินที่รับเพียงพอกับยอดที่ต้องชำระหรือไม่<br><br>**AC-02:** เงินไม่เพียงพอ <br>• **Given** ยอดเงินที่ต้องชำระมากกว่าจำนวนเงินที่ลูกค้าจ่าย<br>• **When** พนักงานยืนยันการชำระเงิน<br>Then ระบบต้องแสดงข้อความว่า "จำนวนเงินไม่เพียงพอ" และไม่บันทึกการชำระเงิน<br><br>**AC-03:** คำนวณเงินทอน <br> • **Given** จำนวนเงินที่ลูกค้าจ่ายมากกว่าหรือเท่ากับยอดที่ต้องชำระ<br>• **When** พนักงานยืนยันการชำระเงิน<br>• **Then** ระบบต้องคำนวณเงินทอนจากจำนวนเงินที่รับลบด้วยยอดที่ต้องชำระ |
| **US-05: ตรวจสอบวัตถุดิบ** | **As a:** พนักงาน<br>**I want:** ให้ระบบตรวจสอบวัตถุดิบก่อนยืนยันออเดอร์<br>**So that:** ไม่รับออเดอร์ที่ไม่สามารถจัดเตรียมได้ | **AC-01:** วัตถุดิบเพียงพอ <br>• **Given** พนักงานกำลังยืนยันออเดอร์<br>• **When** ระบบตรวจสอบแล้วพบว่าวัตถุดิบของสินค้าทุกรายการมีเพียงพอ<br>• **Then** ระบบต้องอนุญาตให้ยืนยันออเดอร์ได้<br><br>**AC-02:** วัตถุดิบไม่เพียงพอ <br>• **Given** พนักงานกำลังยืนยันออเดอร์<br>• **When** ระบบตรวจสอบแล้วพบว่าวัตถุดิบของสินค้าใดไม่เพียงพอ<br>• **Then** ระบบต้องแสดงข้อความว่า "วัตถุดิบไม่เพียงพอ" และไม่อนุญาตให้ยืนยันออเดอร์ |
| **US-06: บันทึกและดำเนินการออเดอร์** | **As a:** พนักงาน<br>**I want:** ให้ระบบบันทึกออเดอร์ ส่งข้อมูลให้บาริสต้า และออกใบเสร็จ<br>**So that:** ออเดอร์สามารถดำเนินการต่อและลูกค้าได้รับหลักฐานการชำระเงิน | **AC-01:** บันทึกออเดอร์ <br>• **Given** พนักงานรับออเดอร์และลูกค้าชำระเงินสำเร็จ<br>• **When** ระบบยืนยันการชำระเงิน<br>• **Then** ระบบต้องบันทึกออเดอร์และสถานะการชำระเงิน<br><br>**AC-02:** ส่งออเดอร์ให้บาริสต้า <br>• **Given** ออเดอร์ถูกบันทึกและชำระเงินสำเร็จ<br>• **When** ระบบดำเนินการหลังจากยืนยันการชำระเงิน<br>• **Then** ระบบต้องส่งข้อมูลออเดอร์ไปยังบาริสต้า<br><br>**AC-03:** ออกใบเสร็จ <br>• **Given** ลูกค้าชำระเงินสำเร็จและระบบบันทึกออเดอร์แล้ว<br>• **When** ระบบดำเนินการหลังการชำระเงิน<br>• **Then** ระบบต้องออกใบเสร็จให้ลูกค้า |
